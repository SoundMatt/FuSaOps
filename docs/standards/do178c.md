# DO-178C — Software considerations in airborne systems

FuSaOps aggregates the DO-178C objective evidence each language tool produces
across a mixed-language codebase.

## How FuSaOps contributes

| DO-178C area | FuSaOps contribution |
|---|---|
| Table A-5 (verification of outputs) | Aggregates each tool's static-analysis / coding-standard findings |
| §6.4.4 (structural coverage) | Each tool reports coverage; FuSaOps surfaces them per component |
| §6.4.4.3 (data/control coupling) | Each tool's `coupling` evidence is collected per language |
| §11.20 (SAS) / §11.16 (SCI) | Each tool generates these; FuSaOps presents the aggregate evidence set |
| Tool qualification (§12.2) | `docs/qualification.md` covers FuSaOps; each tool qualifies separately |

## Notes

DO-178C Annex A objective gap assessment is produced per language by that tool
(e.g. `gofusa do178`). FuSaOps runs the tools and aggregates; a skipped
component is an explicit gap against the objectives for that language.
